## 0. 一页纸

如果只记五句话：

1. **按文件并行的多 agent 开发可行**：契约 + 所有权 + 验收 + git 审计，3 个 agent 可以零冲突交付。
2. **通信不能替代原子性，锁不能替代语义合并**：广播意图约等于无效；租约才能让丢更新归零；锁能防同时写，但防不了“两个人都想改同一行”。
3. **先测 headroom，再谈动态组织**：组织选择是权变的，但动态重组的收益上限可能接近 0。
4. **没有 trace，优化就是拍脑袋**：估计器/门控在玩具数据上有效，但真实 token/cost 还没接。
5. **协调器已经能跑**：P0 有 91 个测试、MCP + CLI、三次真实 agent live demo；V1 Core 前六块已落地，**DSH 5 个任务 + Codex 1 个任务 + 3-agent 并发全部合入；Codex App Server adapter 跑通 V1；真实 Git cherry-pick + 回滚已接 Coordinator；Electron 崩，WebView2 壳已跑通 Start Run/Approve/Merge**。

## 1. 五组实验的关键结论

| # | 实验 | 结论 |
| --- | --- | --- |
| 1 | 3 agent 同工作空间开发 | 6 分钟、485 行实现、856 行测试、91 个测试全绿、0 手工冲突 |
| 2 | 同一文件并发写 | 裸读改写 180 次期望只成功 67/67/68（丢约 62%）；加锁 180/180 |
| 3 | A2A 两跳调用 | 通信层可行（client → audit → ledger），但不解决文件一致性 |
| 4 | 通信 vs 原子性 | 纯广播 52.2% vs 同节奏对照 52.4%（≈无效）；租约 0% 丢更新 |
| 5 | 同一 Markdown 并发编辑 | 锁保住“不丢追加”，但静默覆盖“改同一行”；MVCC 能检测冲突 |

两个反直觉结果：

- **动态组织仿真 headroom ≈ 0**：oracle 0.804 = best fixed 0.804，adaptive 0.800。先别急着做“自动重组”。
- **学习策略不是越多越好**：N=100 时 RF/GBR regret 0.0086，贪心 0.0092；数据少时线性模型反而稳。

## 2. 我们做出来的东西

`p0-coordinator/`：一个可运行的协调内核。

- **协调**：任务卡、写集、依赖、原子 claim、TTL 租约、fencing token、事件日志；
- **遥测**：`runs` 记录 cost/quality/duration/diff，`estimate.py` 聚合 worker/kind 先验；
- **排期**：MILP（依赖/容量/写集互斥/质量下限）+ 2D/3D Pareto + 计划回写/reservation；
- **验证**：独立 verifier 跑 `file_exists/contains/regex/command`；command 有 allowlist、无 shell、timeout、输出上限、环境变量白名单；
- **审批**：N-of-M 不同 approver、TTL 过期、`request_approvals` 重发；
- **预算**：项目 `budget_usd`，已花费 ≥ 预算时 `claim_task` 返回 `budget_exceeded`；
- **V1 Core 切片**：`executions`（Run/generation）+ `file_reservations`（repo/path/父子目录/大小写）+ `candidates`/`evidence`/`merge_attempts`（SHA 冻结、证据绑定、人工批准、合入）+ `workspaces`（真实 git worktree/越界 diff）+ `lifecycle`（V1 Task 状态机）+ `write_set`/预约双重门；
- **Adapter / Desktop**：DSH 5 个任务 + Codex（DeepSeek）1 个任务 + 3-agent 并发 + Codex App Server smoke 已跑通（usage 已记录，cost 按官方价目表估算约 ¥0.0305）；Electron 28/45 已装但窗口崩溃；
- **双入口**：MCP stdio server + `worker_cli.py`（shell agent 可直接调用）。

测试：**91 个全绿**。

## 3. 三次真实 agent live demo

| demo | 链路 | 结果 |
| --- | --- | --- |
| baseline | 3 agents claim → write → commit | 3/3 done，3 条 runs |
| verified | 3 agents → verification → verifier checks | 3/3 checks 通过；第一次 root 配错，3 个任务被正确打回 ready |
| governance | 3 agents → verification → 2-of-2 审批 | alice + bob 各签一次，3/3 done |

真实发现：Windows PowerShell 5.1 会吞掉 `--run '{"..."}'` 里的双引号。CLI 后来加了 `--duration/--quality/--diff-lines/--files-changed` 简单参数。**工具接口要按 agent 的实际 shell 设计。**

## 4. 现在还没解决

- **真实 token/cost**：DSH/Codex usage 已记录；cost 按 DeepSeek 官方价目表估算，尚未做账单级核对；
- **审批角色/顺序/自动升级**：现在只有 N-of-M + TTL；
- **跨机/权限**：单机 SQLite；worker 名字不是身份；
- **Document Kernel**：章节级 lease + MVCC + 合并队列还没实现；
- **排期规模**：CBC 在 6 任务玩具算例上跑通，50 任务/CP-SAT 还没做。

## 6. 想请你们拍砖的三个问题

1. **worktree 隔离 vs 同工作空间协调**：Agent Guild 选 worktree，我们验证了同工作空间 + 写集/租约也可行；边界应该画在哪？
2. **真实 token/cost 采集**：应该放在 agent adapter、harness，还是协调器？没有这个，预算/学习都是模型。
3. **验证 + 审批会不会太重**：小团队里，独立 verifier + N-of-2 审批的收益是否覆盖协作成本？
