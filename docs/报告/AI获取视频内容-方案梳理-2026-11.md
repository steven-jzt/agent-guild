# AI 获取视频内容：2026 年 11 月的方案地图

> 一句话结论：**"AI 看视频"已经分裂成四条路线——原生视频输入（正在 agentic 化）、抽帧喂图、预处理索引、只取语音。选哪条，取决于你要的是"说了什么"还是"画面里有什么"，以及你是"问一次"还是"反复问"。**

---

## 一、先把问题拆开：视频内容其实是三样东西

很多人说"让 AI 看懂视频"，实际混了三种需求：

| 层 | 内容 | 最合适的通道 | 备注 |
|---|---|---|---|
| 声音层 | 口播、对话、旁白、环境音 | ASR / 平台字幕 / 原生音频 | 信息密度最高，成本最低 |
| 画面层 | PPT、演示、人物动作、场景、字幕卡 | 抽帧 + VLM / 原生视频 | 贵，且容易丢帧 |
| 结构层 | 第几分钟讲了什么、哪一段可引用 | 索引 + 时间戳检索 | 决定"能不能追问" |

**大部分"AI 总结视频"的需求，80% 的信息在声音层。** 直接上视觉模型是常见的第一笔冤枉钱。

---

## 二、四条技术路线

### 路线 A：原生视频输入（2026 年的主线）

把视频文件/URL 直接丢给多模态模型，模型自己解码画面 + 音频。

- **Google Gemini 3.7 / 3.8 Flash**：2026 年 9 月起上线 **agentic video understanding**——不再按固定 1 FPS 全量读，而是让模型自己决定"看哪段、用几倍速、看帧还是听音频还是读转录"。官方口径：成本最多降 66%、token 最多降 88%、准确率最多升 7%，长视频收益最大。已在 AI Studio 和 Gemini API 开放，一个参数切换 `agentic` 模式。
- **通义 Qwen3-VL-Plus**：标称"超长视频理解"，260K 上下文；Qwen3-VL-Flash 明确支持**单视频最长 1 小时 / 2GB**。
- **豆包 Doubao-Seed-2.0-lite**：家族首款"全模态"模型，视频/图像/音频/文本原生统一理解，音频侧支持 19 语种转写并识别情绪、环境音。

**优点**：接进去就能用，不用自己搭流水线；对"整体理解、事件定位、动作计数"这类任务效果好。
**缺点**：单价高、延迟大（长视频一问几十秒到几分钟）、时间戳精度不可控、对中文方言/专业术语不如专用 ASR。

**准确率参考（Video-MME test）**：Gemini 3 Pro 88.6 / Gemini 2.5 Pro 87.8 / Gemini 2.5 Flash 84.2 / GPT-5 83.3 / GPT-5 mini 77.3 / Claude Sonnet 4.5 74.2 / 开源最好的一档约 71–74。

### 路线 B：抽帧 + 图像模型（最便宜、最可控）

用 ffmpeg 按固定间隔或镜头切分抽帧，拼成 contact sheet（一张图 20–60 格），交给任意视觉模型。

- 优点：成本极低（一次请求几厘钱）、模型可换、可缓存、可离线。
- 缺点：**没有音频**；1 FPS 会漏掉快速剪辑、UI 操作、字幕滚动；帧数一多反而稀释注意力。
- 适用：PPT/录屏/课程/监控这类"画面变化慢、信息在静态帧里"的视频。

### 路线 C：预处理索引 + Agent（"视频上下文层"）

代表是开源的 **videoctx**（Apache-2.0）：用 ffmpeg 关键帧 + PySceneDetect 镜头切分 + faster-whisper 转录 + 可选 VLM 画面描述，生成一个 `.vctx` 目录（JSON + JPEG），之后任何模型都能查。

- 索引一次（约 $0.10–0.25/小时视频），之后每个问题约 $0.02，长视频追问成本几乎不变。
- 自带 MCP server：`video_overview` / `survey_video` / `get_frames` / `transcript_search` / `find_moments`，可直接挂给 Claude Code、Cursor 这类 agent。
- 它自己在 Video-MME 上的实测（2026-10）：短视频 84.7%（$0.025/问），长视频 83.3%（冷启动 $0.109，追问 $0.021）；同场景下 Gemini Flash-Lite 原生只有 70% / 76.7%，但**原生在长视频上单价更低（$0.022）**。结论是：**索引赢在"反复问"，原生赢在"只问一次"**。

### 路线 D：只取语音（性价比之王）

- 平台字幕：YouTube / B 站大多有 CC 字幕或 AI 字幕，直接抓，零成本，但错字多、时间轴粗。
- 云端 ASR：通义听悟 **0.6 元/小时**（含说话人分离、语种识别），加章节速览/摘要每项 0.064 元/小时，视频 PPT 提取 0.64 元/小时。
- 本地 ASR：faster-whisper / whisper.cpp，large-v3 中文效果够用，零边际成本，隐私安全。
- 这一步拿到的带时间戳文本，才是后面做摘要、做文章、做检索的地基。

## 三、横向对比

| 路线 | 每小时成本（量级） | 画面理解 | 音频理解 | 时间戳 | 反复追问 | 上手难度 |
|---|---|---|---|---|---|---|
| A 原生（agentic） | ¥0.6–5 | 强 | 中 | 中 | 每次重算 | 低 |
| A 原生（普通 1fps） | ¥5 左右 | 强 | 中 | 中 | 每次重算 | 低 |
| B 抽帧 + VLM | ¥0.3–1 | 中（丢帧） | 无 | 准（你给的） | 便宜 | 中 |
| C 索引 + Agent | 首次 ¥1–2，之后 ¥0.15/问 | 中 | 强（ASR） | 准 | 最便宜 | 高 |
| D 仅 ASR/字幕 | ¥0–0.6 | 无 | 强 | 准 | 便宜 | 低 |

> 成本按 Gemini 3.7 Flash（$0.75/M 输入）与 258 token/帧、1 FPS 估算：1 小时视频全量约 93 万 token ≈ $0.70 ≈ ¥5；agentic 模式按 -88% 约 ¥0.6。国产 Qwen3-VL-Flash（$0.05/M）全量喂约 ¥0.35/小时，是目前最便宜的"原生视频"选项。价格随时变，下单前以官网为准。

## 四、真实世界的六个坑

1. **token 爆炸**：1 小时 1 FPS ≈ 90 万 token。不做切块/降采样，要么超上下文，要么账单失控。
2. **1 FPS 丢关键帧**：快速剪辑、代码滚动、UI 弹窗，1 秒内发生的事全没了。要么 0.25–0.5 FPS，要么按镜头切分。
3. **音频被低估**：原生视频模型的中文听写普遍不如专用 ASR；方言、术语、多人抢话更明显。**画面 + 独立 ASR 双通道，通常比纯原生准。**
4. **时间戳幻觉**：模型爱编"第 3 分 20 秒"，实际画面在 5 分 10 秒。要么让它引用你提供的帧号/字幕段号，要么后验抽检。
5. **OCR 要用 OCR**：PPT、报表、聊天记录，专用 OCR 比 VLM 又准又便宜，别让视觉模型硬读。
6. **合规**：下载、转写、二次分发第三方视频涉及平台条款与版权；商用尤其要谨慎，内部研究和个人学习风险低得多。

## 五、按场景选型

| 你的场景 | 推荐组合 | 理由 |
|---|---|---|
| 把视频变成公众号文章/口播稿 | 平台字幕或 ASR + 关键帧少量补充 | 信息在语音，1 元/小时以内搞定 |
| 课程/讲座/会议长视频，要反复查 | 路线 C：索引一次，之后问答 | 追问成本降一个数量级 |
| 少量视频，要最准、懒得搭 | Gemini 3.7/3.8 Flash agentic（或 Qwen3-VL-Plus） | 一个 API 调用，长视频性价比最好 |
| 大批量、隐私敏感、离线 | faster-whisper + 抽帧 + 开源 VLM（Qwen3-VL-8B/32B） | 零边际成本，数据不出内网 |
| 录屏/教程/软件演示 | 抽帧 + OCR + ASR 三件套 | 画面文字比画面语义重要 |
| 短视频批量拆解（选题、脚本结构） | ASR + 镜头切分 + 首帧/尾帧 | 节奏和钩子比画面细节重要 |

## 六、最小可用流水线（本地可跑）

```bash
# 1) 取视频（示例：任意 yt-dlp 支持的站点）
yt-dlp -f "bv*[height<=720]+ba/b" -o "v.%(ext)s" "<URL>"

# 2) 抽音频
ffmpeg -i v.mp4 -vn -ac 1 -ar 16000 a.wav

# 3) 转写（带时间戳）
faster-whisper a.wav --model large-v3 --language zh --output_format srt

# 4) 镜头切分 + 关键帧
ffmpeg -i v.mp4 -vf "select='gt(scene,0.3)',scale=512:-1" -vsync vfr frames/%04d.jpg

# 5) 每帧配一句描述（任意 VLM，可批量）
#    输入：帧号 + 时间码；输出：一句话 + 是否含文字/图表
```

最后把「字幕段落 + 帧描述」按时间轴合并成一份**带时间码的大纲**，再交给文本模型写文章/做摘要。这条链路的总成本大约是 **0.5–1.5 元/小时视频**，且每一句都能回溯到具体时间点。

如果不想自己搭：`videoctx`（索引 + MCP）、`video-vision-mcp`（ffmpeg 抽帧 + whisper + 可选 Gemini 原生分析，自动三档降级）、`mcp-video-frames`（纯抽帧 MCP）都能直接挂到 agent 上用。

## 七、趋势判断（未来 6–12 个月）

1. **agentic 采样会成为默认**，固定 FPS 全量喂会像"逐像素比对"一样被淘汰。Google 已经把它做成一个参数，其他家会跟。
2. **"视频上下文层"会标准化**：一次索引、任意模型查询、可缓存可迁移。`.vctx` 这类开放格式如果被 agent 生态接受，会催生"视频版 RAG"。
3. **全模态单模型**（豆包 Seed 2.0 这类）会吃掉"视频 + 音频 + 文本"的拼接管线，但专用 ASR/OCR 仍会在准确率和成本上守住位置。
4. **token 压缩研究落地**（SURGE 等 ICLR 2026 工作）：同等准确率下 token 再降一个量级，长视频从"奢侈品"变"日用品"。
5. **入口上移**：YouTube 的 "Ask YouTube"、各家的视频问答，会把能力直接塞进播放器，独立工具的空间被压缩到"批量、私有、可编程"。
