# 第二轮交付：停止后的核对与恢复

日期：2026-11-13（Asia/Shanghai）。分支 `codex/p2-2-recovery`，基于第一轮 `84421d8`。先审查第一轮 PR，再审查本轮增量；未将任一轮自动合并到 main。

## 做了什么

WebView2 增加“停止后的核对与恢复”区域，启动、刷新及请求失败后读取遗留执行和合入记录。读取本身不修改业务状态，不调用模型、不重发任务、不重新准备或发布代码。

执行记录区展示 ID、任务、运行代次、工作区与已识别改动，并区分“进程仍在运行”“所属进程已退出”“需要手工核对”。经核对后显式记录 interrupted，任务转 needs_fix，保留工作区、候选和文件预约。仍在运行的已识别进程不能被人工确认覆盖；旧记录无归属信息时，要求填写说明并明确勾选本地进程及其子进程已停止。重复收尾、错误代次、旧执行影响新运行、已关闭任务均拒绝。

合入区显示真实目标 SHA、准备 SHA 和恢复状态。只有真实目标等于保存结果、原审批证据仍有效时，才允许补全 succeeded/accepted。恢复入口通过 require_published 检查，禁止把“确认记录”变成重新发布。已准备但尚未发布的 pending attempt 可显式放弃，保留候选与代码。目标变化、凭据缺失和准备未完成时继续阻止，不自动重跑或回滚。

## 当前架构和接口

- Python 协调内核继续负责 SQLite 状态、候选门禁和 Git 两阶段合入；恢复的只读进程/凭据检查放在独立 `recovery.py`，收尾与状态转移在同一数据库事务中检查。
- WebView2 的 JobHost 请求增加唯一 request_id，在数据库旁的 `request-receipts/` 原子保存宿主 PID、创建 FILETIME 与本地退出状态。worker 把请求关联、自己的 PID 和创建时间写入 Execution.meta；不保存密钥或完整环境。
- 核对 PID 时同时比较创建时间；PID 被重用不会误认为旧进程仍存在。可信版本的宿主与 worker 均已退出时可确认本地执行树已停止；信息不足、权限不足、损坏或不匹配的凭据保留 unknown，进程仍活着时禁止收尾。
- 增加 CLI/MCP 对应入口：`recovery-report` / `recovery_report`、`reconcile-execution` / `reconcile_execution`、`reconcile-merge` / `reconcile_merge`。执行收尾必须携带当前 generation 与说明，合入收尾必须携带准备结果 SHA。
- 保留原 finish_execution/finish_merge 接口。普通合入确认仍可发布；只有恢复入口限定“已经发布后补记录”。GUI/CLI/JobHost 二进制已重新构建。
- MCP 将 PuLP 变为调用 MILP 工具时才导入，恢复和其他工具不因缺少可选求解器而无法启动；未安装或升级依赖。
- Electron 增加恢复命令到 CLI 的转发，但未进行完整 Electron 窗口验收，也未统一两套运行时。

## 使用与恢复步骤

先刷新界面，检查工作区改动与本地进程。进程仍活着时继续等待或停止所属请求；不要结束不属于本次执行的进程。只有确认本地执行已停止后才填写说明并收尾。这个动作不撤销远端模型任务，也不回滚已有文件修改。

```powershell
py -3.13 -X utf8 worker_cli.py --db DB recovery-report --project PROJECT
py -3.13 -X utf8 worker_cli.py --db DB reconcile-execution --execution EXECUTION --generation GENERATION --reason "进程和工作区均已核对"
# 仅旧记录或归属不足、且操作员已手工确认时追加 --confirm-local-stopped
py -3.13 -X utf8 worker_cli.py --db DB reconcile-merge --attempt ATTEMPT --action confirm --result-sha PREPARED_SHA
# 只有准备但未发布的 pending 合入可显式放弃
py -3.13 -X utf8 worker_cli.py --db DB reconcile-merge --attempt ATTEMPT --action abandon --result-sha PREPARED_SHA --reason "核对后放弃本次合入"
```
