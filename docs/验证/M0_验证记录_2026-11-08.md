## 5. 已修复的问题与设计依据

### Windows 执行进程树

仅终止普通 Node 子进程不足以保证清理其分离启动的后代。实现原生 Job Object 助手：先挂起创建执行进程，分配到禁用 breakaway 的 Job 后再恢复；宿主退出或所有者退出时终止该执行树。自动化测试实际启动后代进程，并确认所有者死亡后子、孙进程消失。

这是执行生命周期管理，不是操作系统安全沙箱。无法据此声称 Agent 没有其他文件或网络权限。

### Windows 打包应用的目录重定向

本机桌面应用写入名义上的 LocalAppData 时，系统实际重定向到包的 LocalCache。父进程可访问名义路径，Codex 限权执行用户却收到 `CreateProcessWithLogonW failed: 267`。

通过文件标识与 `realpathSync.native` 确认两路径指向同一目录后，统一解析实验根目录及工作区的物理路径，再传给进程与沙箱。没有硬编码包目录或关闭沙箱。新增目录别名回归测试：修复前断言失败，修复后通过；真实 Codex 停止/接续也随后通过。

### 协议成功与任务成功分离

DSH 的 `session/wait` 可成功返回，随后状态为 idle，但 `turn/end` 仍携带模型鉴权错误。新增错误提取，避免将 AUTH / 401 隐藏在“没有修改文件”的后续错误下。原始 API 失败记录保持原样；修复后未重复调用失效密钥。

JSON-RPC 按请求 ID 匹配，超时不自动重试；畸形响应会中止传输。Codex 在发送回合前订阅完成通知，覆盖“完成通知早于开始确认”的时序。关闭传输拒绝待处理请求，失效问题不能重复回答。

## 7. 已知兼容与依赖限制

1. **DSH 客户端与 Runtime 发布版本不同。** 官方客户端 0.0.1-rc.1 可完成基本任务，但未公开当前 Runtime 的原生问题回调。因此基本接入实验使用该官方客户端；平台交互适配器通过同一 Runtime 的官方 stdio SDK 协议实现回调，未修改 Runtime，也未另写 Agent 执行引擎。升级前必须复跑协议测试。
2. **上游声明缺失。** 已发布客户端声明引用本地无法解析的 `dsh-sandbox`、`dsh-tasks`。当前启用 `skipLibCheck` 跳过第三方声明内部检查；自有源码保持 strict。不能将此解释为依赖声明完全通过类型验证。
3. **依赖审计未清零。** 首次 M0 实施时 `npm audit --json` 汇总受影响依赖项 209：high 198、moderate 11、critical 0，包含传递影响，并非 209 个独立漏洞编号。涉及 `undici`、`zod`、`fflate`、`@modelcontextprotocol/client` 等及其依赖链。保留锁定版本以保证实验可复现，没有强制执行破坏性的版本升级。本次密钥复测未变更依赖，也未重新执行依赖审计。正式分发前需要选择修复后的上游版本并验证兼容；当前不能作为发布就绪依据。
4. **实验并非完整平台。** 适配器未实现任务并发、持久状态、占用恢复或合并防线。当前事件存在内存和本机 JSON 文件中；日志容量、崩溃恢复等需要后续平台阶段实现。

协议资料：[Codex app-server 文档](https://learn.chatgpt.com/docs/app-server)。DSH 接入以本机锁定的官方 npm 包及其声明、协议实现为验证对象；不假定上游主分支文档与已发布客户端完全一致。
