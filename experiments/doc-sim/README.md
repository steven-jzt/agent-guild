# doc-sim：同一份 Markdown 的并发编辑实验

3 个 agent 改同一份文档，比较 4 种并发控制策略：

- `none`：无协调，最后写赢；
- `global`：整篇文档一把互斥锁；
- `section`：章节级锁；
- `mvcc`：读快照 + 提交时版本校验 + 追加合并。

两个场景：

1. **append**：12 个任务各追加一行唯一标记，测“丢更新 / 吞吐”；
2. **replace**：3 个 agent 抢改同一行 `Status`，测“是否发现意图冲突”。

## 运行

```powershell
python doc_sim.py
```

无第三方依赖。

## 结果（30 个种子）

追加场景：

| 策略 | 保留 / 12 | 丢失 | 重试 | 耗时 |
| --- | ---: | ---: | ---: | ---: |
| none | 8.5 | 3.5 | 0 | 25.9ms |
| global | 12.0 | 0 | 0 | 69.6ms |
| section | 12.0 | 0 | 0 | 31.8ms |
| mvcc | 12.0 | 0 | 3.4 | 25.7ms |

改同一行场景：

| 策略 | 检测 | 静默覆盖 |
| --- | ---: | ---: |
| none / global / section | 0 | 4 |
| mvcc | 4 | 0 |

**结论**：锁保证原子性，但不保证冲突感知；MVCC 能检测冲突，但 first-writer-wins 会让后写者白做；语义合并/裁决要单独建。

> 这是机制级仿真（线程 + 模拟延迟），不是真实 LLM。目的是比较协议，不是比较模型。
